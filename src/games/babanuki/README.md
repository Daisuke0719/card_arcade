# ババ抜き（babanuki）

担当: 担当1 / Issue #1（CPU対戦）、Issue #36（オンライン対戦）

## 遊び方

ゲームの入口で「CPU対戦」と「オンライン対戦」を選べます。以下は CPU 対戦の説明です。
オンライン対戦の違いは「オンライン対戦」の節にまとめています。

53枚（52枚 + 赤ジョーカー1枚）を4人（あなた + CPU 3人）に配り切ります。配った直後に、
各プレイヤーの手札から同じ数字のペアが自動で捨てられた状態でゲームが始まります。

自分の手番では、左隣のプレイヤーの裏向きの手札から1枚を選んでクリックし、1枚引きます。
引いたカードとペアがそろえば、その場で2枚とも捨てられます。手札が0枚になったプレイヤーは
その時点で上がりになり、以降は手番も引かれる対象にもなりません。

最後まで残った1人がジョーカーを持ったまま最下位になります。上がった順に1位から4位までの
順位が結果画面に表示されます。

## ルール

このリポジトリで採用したルールです。

- ジョーカーは赤1枚だけを使用します（黒のジョーカーは使いません）。
- ペアの条件は「同じランクが2枚」です。スート（マーク）と色は問いません。
- 同じランクが3枚あるときは、先頭の2枚だけ捨てて1枚を手札に残します。
- 同じランクが4枚あるときは、2ペアとも捨てて0枚にします。
- ジョーカーはどのカードともペアにならず、いずれかのプレイヤーの手札に残ります。
- 引く相手は左隣に固定です。自分で相手や方向を選ぶことはできません。
- 引く相手がすでに上がっていた場合は、その次に残っているプレイヤーから引きます。
- カードを引いた人の手札は、ペアを捨てたあとに並びを混ぜます。引いたカードの位置から、
  ジョーカーの場所が引かれた側に分からないようにするためです。

今回は実装しないローカルルールは `docs/games/babanuki.md` に記載のとおりです
（ジョーカー2枚、色を揃える必要のあるペア、引く相手を自分で選ぶ、など）。

## オンライン対戦

2〜4人の参加者が全員人間として遊びます。CPU は参加しません。配り方、ペアの捨て方、
左隣から引くルールは CPU 対戦と同じです。

- 相手の手札は裏向きの枚数だけが届きます。カードを引くときは、カードではなく手札の位置を送ります。
- 引いたカードは、引いた本人の画面にだけ表向きで表示します。他の参加者の画面には
  「〇〇が1枚引きました」とだけ表示します。CPU 対戦でも、CPU が引いたカードは表示しません。
- ルームの作成・参加、再接続、再戦は共通ロビーの機能を使います。再戦はルーム作成者が
  結果画面の「同じルームで再戦」から始めます。

## 実装メモ

- `logic.ts` の `BabanukiState` は、手札（`hands`）と手番・上がった順（`turn: TurnState`）、
  進行段階（`phase`）を持ちます。`phase` は `"playing"`（入力待ち）→ `"revealing"`（引いた
  カードを見せている間）→ `"playing"` を繰り返し、生存者が1人になったら `"finished"` になります。
- ペア判定は `discardPairs` に集約しています。`partitionJokers` でジョーカーを分けたうえで
  `groupByRank` で同ランクをまとめ、2枚単位で捨てます。残ったカードは元の並びのままで、
  ジョーカーを末尾へ移しません。
- 引いた人の手札の並べ替えには ``createRng(`${seed}:${drawCount}:hand`)`` を使い、CPU が引く位置を
  選ぶ乱数とは種を分けています。
- 引いた人が上がると `finishPlayer` が手番を次の人へ移します。そのため、`revealing` から戻る
  `tick` では、手番が引いた人（`lastDrawerId`）のままのときだけ `nextTurn` を呼びます。
- 「左隣から引く」「上がった人を飛ばす」は `@core` の `neighborId` / `finishPlayer` に任せています。
  自作の判定は書いていません。
- CPU がどの位置を引くかは `cpu.ts` の `chooseDrawIndex` に分けています。乱数は
  `createRng(state.seed + state.drawCount)` で作るため、`logic.ts` 側は `Math.random()` を
  使いません。
- CPU の手番の進行は `BabanukiGame.tsx` の `useCpuTurn(pendingDelayMs(state), ...)` の1行だけで、
  `.tsx` に `setTimeout` は書いていません。
- テストでは、ペア判定（2枚 / 3枚 / ジョーカー）、引いた直後の即時ペア処理、上がった人のスキップ、
  上がった順の順位付け、CPU の手番中に `draw` を送っても状態が変わらないことを確認しています。
- 画面は `BabanukiScreen.tsx` に1つだけ作り、CPU 対戦（`BabanukiGame.tsx`）とオンライン対戦
  （`BabanukiOnlineView.tsx`）の両方から使います。どちらも `logic.ts` の `toPublicState` で作った
  `BabanukiView` を渡すので、CPU 対戦でも相手のカードの中身は画面に届きません。
- `onlineAdapter.ts` は `logic.ts` の `createStateForPlayers` / `reduce` / `pendingDelayMs` /
  `toPublicState` をそのまま使い、Action の形式・手番・位置の範囲・試合終了後の操作の検証だけを
  足しています。引いたカードを見せる 700ms は `pendingDelayMs` と `tick` でサーバーが進めます。
- オンライン対戦のテストは `onlineAdapter.test.ts`（合法操作・不正操作・終了判定・非公開情報）と
  `BabanukiOnlineView.test.tsx`（送信・操作の無効化・再戦）にあります。

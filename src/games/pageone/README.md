# ページワン（pageone）

担当: 担当9 / Issue #10

## 遊び方

プレイヤー1人と CPU 3人の4人で対戦します。52枚を5枚ずつ配り、山札から1枚めくったものが最初の場札です。

自分の番になったら、場札と同じマークか同じ数字のカードをクリックして出します。出せないカードは押せません。出せるカードが1枚も無いときだけ「山札から引く」を押せます。引いたカードがそのまま出せる場合は、自動的に場に出ます。

先に手札を0枚にした人が勝ちで、その時点でゲームが終わります。結果画面には4人の順位が出ます。「もう一度」を押すと新しい配りで始まります。

## ルール

このゲームで採用したルールです。

- 場札と**同じマーク**か**同じ数字**のカードだけ出せる（`canPlay`）
- 出せるカードがあるときは山札を引けない。1枚も無いときだけ引ける
- 引いたカードが出せるときは、その場で必ず出す（手札に残せない）
- **8**: 出すと次の人の手番を1回飛ばす
- **A**: 出すと同じ人がもう1枚出せる。出せる限り何枚でも続く
- 山札が尽きたら、場札の一番上だけを残して残りを混ぜ、山札に戻して続ける
- 場札が1枚だけで山札も空のときは、引かずに手番を次の人へ移す
- 最初にめくった場札が8やAでも効果は発動しない
- 最後の1枚が8やAでも、上がった時点で終了して効果は適用しない
- 1人が上がった時点で終了し、2位以下は手札の枚数が少ない順（同数は同順位）

今回は実装しないローカルルールです。

- リバース、ドロー2 / ドロー4、ワイルドカード、出したあとのマーク指定
- 残り1枚のときの宣言義務
- 8 と A 以外の特殊カード、ジョーカー
- 同じ数字を複数枚まとめて出す
- 全員が上がるまで続ける、山札切れで終了する、得点計算と複数回戦

## 実装メモ

### 状態の持ち方

`PageOneState` は、山札 `deck`、場札 `field`（末尾が一番上）、プレイヤーIDごとの手札 `hands`、手番 `turn`、`phase`、`winnerId`、進行ログ `log`、引いた回数 `drawCount`、`seed` を持ちます。手番は自作せず `@core` の `TurnState` に任せ、`nextTurn` で進めます。

### 特殊カードは手番の進み方で表す

8とAを `applyPlay` の中で分岐させると、特殊カードが増えるたびに分岐も増えます。そこで「手番を何人分進めるか」の違いとして扱い、`stepsOf(card)` が 8 で 2、A で 0、それ以外で 1 を返します。`applyPlay` は「カードを場に置く → `advanceTurn(state, stepsOf(card))`」の順で処理するだけです。

### 判定の中心になっている関数

- `canPlay(card, field)`: `sameSuit || sameRank` の1行
- `legalMoves(hand, field)`: 出せるカードの一覧。0件のときだけ引ける
- `drawFromDeck`: 山札が空なら場札を混ぜ直してから引き、引いたカードが出せれば `applyPlay` に渡す
- `pendingDelayMs`: 手番が CPU のときだけ `CPU_DELAY_MS` を返す

### 乱数と時間

`logic.ts` では `Math.random()` を使わず、混ぜ直しは `createRng(state.seed + state.drawCount)`、CPU の選択は `createRng(state.seed + state.drawCount * 31 + state.field.length)` のように状態から決まる seed で乱数を作ります。時間は画面側の `useCpuTurn(pendingDelayMs(state), () => dispatch({ type: "tick" }))` の1行だけが扱い、`.tsx` に `setTimeout` は書きません。

### CPU の考え方

`cpu.ts` の `chooseCard(moves, rng)` は、出せる候補から `pickRandom` で1枚選ぶだけです。候補が空なら `null` を返し、`logic.ts` 側で山札を引く処理に移ります。

### テストで守っていること

`logic.test.ts` では、`card` / `hand` で `PageOneState` を組み立ててから `reduce` を呼びます。8やAを狙って出す状況は初期配りからは作れないためです。判定の3件に加えて、山札から引く動作、引いたカードの自動プレイ、山札切れの混ぜ直し、8とAの効果、上がりと順位を確認します。受け付けない操作（出せるのに引く、手番でないのに出す、出せないカードを出す）も、状態が変わらないことをテストしています。最後に決着まで自動で進める確認を入れ、合計52枚が保たれることを検証しています。

# ハイ＆ロー（example-game）

運営が用意した**お手本**です。担当ゲームを実装するときは、まずこのフォルダを読んでください。
6ゲームすべてで使う型がこの1本に入っています。

## 遊び方

1. 表向きのカードを見て、次のカードが「高い」か「低い」かを選びます。
2. CPU も同時に予想します。当たった人だけが1点を獲得します。
3. 同じ数字が出たときは引き分けで、どちらも点になりません。
4. 全10ラウンドを終えて、得点が多いほうが勝ちです。

## 状態の持ち方

状態は `logic.ts` の `ExampleState` 1つにまとめ、`reduce(state, action)` だけで進めます。

```text
guessing  … 人間の入力待ち（pendingDelayMs は null）
  ↓ guess
revealing … カードをめくって見せている（pendingDelayMs は 900）
  ↓ tick
guessing または finished
```

画面側は「今どのフェーズか」を見て表示を変えるだけで、勝敗の判断は一切しません。

## なぜ logic を分けるのか

`logic.ts` には **React も時間も乱数も入れません**。

- `reduce()` は「状態 + 行動 → 新しい状態」を返すだけの純粋関数なので、
  テストは `reduce` を続けて呼ぶだけで書けます。`setTimeout` をテストする必要がありません。
- 待ち時間は `pendingDelayMs(state)` が「何ミリ秒後に自動で進むべきか」を返し、
  画面側が `useCpuTurn(pendingDelayMs(state), () => dispatch({ type: "tick" }))` の1行で実行します。
  アプリの中でタイマーを使っているのは、この共通フックだけです。
- 乱数は `createRng(seed)` を使い、seed を固定すれば毎回同じ展開になります。
  `Math.random()` を `logic.ts` や `cpu.ts` で直接呼ぶと ESLint がエラーにします。

CPU の判断も同じ考え方で、`cpu.ts` を

- `highProbability(card)` … 確率を返す純粋関数（テストするのはこちら）
- `chooseGuess(card, rng)` … 乱数と比べて実際に選ぶ薄い層

に分けています。

## テストで守っているもの

`logic.test.ts` は正常系だけでなく、**壊れやすいところ**を見ています。

- 同じ数字のときに引き分けになる（境界値）
- 判定中にもう一度クリックしても状態が変わらない（連打で先に進めない）
- 山札が尽きたら終了する（異常系）
- 同じ seed なら同じ展開になる（テストが不安定にならない）

自分のゲームでも「正しく動く」ケースだけでなく、**やってはいけない操作が弾かれること**を必ずテストしてください。

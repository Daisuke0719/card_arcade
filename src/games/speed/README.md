# スピード（speed）

担当: 担当6 / Issue #3

## 遊び方

1. 中央に2枚の台札が置かれます。
2. 自分の手札から、左右どちらかの台札と数字が1つ違うカードをクリックして出します。
3. 出したカードが新しい台札になり、自分の山札から1枚引いて手札を4枚に保ちます。
4. CPU は1200ms ごとに出せるカードを自動で出します。
5. どちらも出せなくなったら、各自の山札から1枚ずつ新しい台札に置いて続けます。
6. 先に手札と山札を出し切ったほうが勝ちです。

## ルール

**採用したルール**

- 台札と数字が1つ違うカードだけ出せます（台札 7 に 6 と 8）。
- 同じ数字は出せません（台札 7 に 7 は出せない）。
- A と K はつながります（K → A、A → K）。`cycleRank` で判定。
- スート（マーク）は一切関係ありません。
- 出せるカードは常時ハイライトされます。
- クリック1回で出します。両方の台札に出せるときは左の台札に出ます。
- カードを出したら山札から補充し、手札を4枚に保ちます。山札が空なら補充しません。
- CPU は 1200ms ごとに1回だけ出します。
- 両者とも出せないときは 700ms 後に各自の山札から台札に1枚ずつ置きます。
- 決着：手札と山札が両方0枚になった方の勝ち。デッドロック後に両方の山札が空で出せない場合は、残り枚数が少ない方の勝ち。同数なら引き分け。

**今回は実装しないローカルルール**

- 手札を5枚以上にする（4枚固定）。
- 台札を3枚以上にする（2枚固定）。
- 人間同士の対戦（プレイヤー1人 + CPU のみ）。
- ドラッグ&ドロップで台札を選ぶ（クリック1回・左固定）。
- 同時出し時の速度判定（独立して処理）。
- スート縛り（数字だけで判定）。

## 実装メモ

**状態の持ち方**

- `SpeedState` は `you` / `cpu` / `piles` / `phase` / `winner` / `seed` を持ちます。
- 各プレイヤーの陣営（`SpeedSide`）は `hand` と `deck` を持ちます。
- `piles` は `[左, 右]` の2枚の台札です。
- `phase` が `"playing"` なら進行中、`"finished"` なら終了です。

**判定の中心**

- `canPlay(card, pile)`: 1つ違いを判定。`cycleRank` でA-Kのつながりを処理。
- `playablePileIndex(card, piles)`: どちらの台札に出せるか。両方出せたら0を返す。
- `hasPlayableCard(side, piles)`: その陣営に出せるカードがあるか。
- `refillPiles(state)`: デッドロック時に台札をリフィル。
- `pendingDelayMs(state)`: CPU の手番（1200ms）/ デッドロック待ち（700ms）を判定。

**CPU の考え方**

- 出せるカードの中から最初の1枚を選びます。強い判断は不要です。

**テストで守っていること**

- 1つ違いだけ出せる（同ランク不可）。
- A と K のつながり（双方向）。
- 両方出せるときは左に出る。
- 出せないカードを出しても状態は変わらない（参照の同一性で確認）。

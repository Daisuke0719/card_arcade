提出前の検証を行います。

## 1. 全部入りチェック

```
npm run verify
```

これは CI とまったく同じ内容（範囲チェック → lint → 型 → テスト → ビルド）です。
落ちた場合は、**最初に落ちたものから**直してください。原因が分からないときは `docs/troubleshooting.md` を見てください。

## 2. 変更範囲の確認

```
git status
```

`src/games/<自分のゲームID>/` の外に変更が無いことを確認してください。
外に変更がある場合は `npm run scope` が出す `git restore ...` をそのまま実行して戻します。

## 3. Issue の完了条件と突き合わせる

```
gh issue view $0
```

Issue の「必須要件」と「完了条件」を1つずつ読み、実装とテストが対応しているかを表にしてください。

| 必須要件 | 対応する実装 | 対応するテスト | 状況 |
|---|---|---|---|

**満たしていないものを「満たしている」と書かないでください。** 未達なら未達と書きます。

## 4. テストの中身を点検する

- 正常系だけになっていないか
- 境界値（同じ数字・最後の1枚・0枚）を見ているか
- やってはいけない操作が弾かれることを確認しているか
- `Math.random()` に依存して結果が変わるテストになっていないか

不足があれば、追加すべきテストを具体的なテスト名で提案してください。

## 5. 規約の点検

`rule-checker` サブエージェントを起動して、担当フォルダの差分が規約に沿っているかを別の目で確認してください。

## 6. 報告

- `npm run verify` の結果
- 必須要件の達成状況（表）
- 不足しているテスト
- 人間が実機で確認すべき操作手順（3〜5ステップ）

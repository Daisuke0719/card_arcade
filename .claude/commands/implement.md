人間が合意した計画に沿って実装します。$ARGUMENTS

## 守ること

- 編集してよいのは `src/games/<自分のゲームID>/` の中だけです
- 依存パッケージを追加しません
- `logic.ts` と `cpu.ts` には react / `Math.random()` / `Date.now()` / `setTimeout` を書きません
- 共通機能は `@core` と `@ui` から使います（`src/games/CLAUDE.md` の早見表を見てください）
- 計画に無いことを勝手に足しません。思いついた改善は実装せず、最後に提案として書いてください
- **`npm run dev` と監視モードのテストは実行しません**（ハーネスが止めます）。
  開発サーバーは人間がターミナルB で付けっぱなしにしています。画面の確認は人間に依頼してください

## 進め方

1. **テストから書く。** Issue の必須要件に対応するテストを `logic.test.ts` に書きます。
   このとき、テストが**赤くなること**をまず確認してください（まだ実装が無いので当然赤です）。
2. `logic.ts` を実装してテストを緑にします。
3. `npm test` を実行します。
4. 画面（`<Xxx>Game.tsx`）を作ります。ルール判定を画面に書かないでください。
5. `npm run verify` を実行します。

## 実装が終わったら

次を報告してください。

- 変更したファイルの一覧（`git status` の結果）
- 追加したテストと、それぞれが Issue のどの要件に対応するか
- `npm run verify` の結果
- Issue の必須要件チェックリストと、その達成状況
- まだできていないこと・判断に迷ったこと

## 人間に確認してもらうこと

報告のあと、次を人間に依頼してください。**どれも Claude Code は代われません。**

1. **ターミナルB で動いている開発サーバーのブラウザを再読み込みして、最初から最後まで1回プレイする**
   （http://localhost:5173/ を開いたまま再読み込みするだけです。
   ターミナルB で開発サーバーが止まっていたら、人間が `npm run dev` で起動し直します）
2. テストのアサーションを1つわざと逆にして、赤くなることを確認する
   （ターミナルB で `npm test` を打ちます。直したら必ず元に戻します）
3. Issue の必須要件と実装が一致しているかを目で確認する

**「動きました」と言う前に `npm run verify` が緑であることを必ず確かめてください。**
そして、**緑であることと「遊べること」は別物です。** 遊んだかどうかを知っているのは人間だけです。

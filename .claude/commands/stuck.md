困っている内容: $ARGUMENTS

**このコマンドではコードを変更しません。** 状況を整理して、人間が判断できる形にするのが目的です。
（詰まっているときに大きな作り直しを始めるのが、研修でいちばん時間を失う失敗です）

## 1. 事実を集める

```
git branch --show-current
git status --short
npm run scope
npm run lint
npm run typecheck
npm test
```

エラーが出たものについて、**最初のエラーメッセージだけ**を正確に引用してください。
（後続のエラーは最初のエラーの影響であることが多いので、まず1つ目を見ます）

## 2. 既知のトラブルと突き合わせる

`docs/troubleshooting.md` を読み、当てはまるものがあれば番号（T-xx）と対処を示してください。

## 3. 切り分ける

次のどれに当たるかを判断してください。

| 分類 | 見分け方 | 次の一手 |
|---|---|---|
| 環境の問題 | `npm run doctor` が赤い | doctor の指示に従う |
| 範囲の問題 | `npm run scope` が赤い | scope が出す `git restore` を実行 |
| 型の問題 | `typecheck` だけ赤い | エラーの最初の1件を読む |
| ルールの解釈 | テストは通るが挙動が期待と違う | Issue の記述を確認する |
| 時間切れ | 必須要件が終わりそうにない | 何を削るかを講師に相談する |

## 4. 報告する

- 何が起きているか（1〜2行）
- 分かっている原因（推測なら「推測」と書く）
- **次の一手を1つだけ**（複数の案を並べない）
- 講師に相談すべきかどうか

直せそうでも、**このコマンドでは直しません。** 人間が判断してから `/implement` で直します。

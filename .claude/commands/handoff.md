今の状況を10行程度にまとめます。使う場面は次の3つです。

- **作業を中断するとき**（休憩、時間切れ、別の作業に移るとき）
- **講師に状況を渡すとき**（中間チェックポイント、詰まって相談するとき）
- **自分が後で再開するとき**（続きから迷わず始められるように）

1人開発なので、交代する相手はいません。**渡す相手は「講師」か「30分後の自分」です。**

## 1. 状態を確認してから書く

推測で書かないでください。まず次を実行します。

```
git branch --show-current
git status --short
git log --oneline -5
npm run scope
```

必要なら Pull Request の状態も見ます。

```
gh pr view --json number,title,isDraft,reviewDecision
```

## 2. 引き継ぎメモの形

```
## 今どこ
- 担当: <ゲームID> / <ゲーム名>
- ブランチ: feature/<ゲームID>
- Issue: #<Issue番号> の Step <1/2/3 のどこまで終わったか>

## 直前にやったこと
- <3行以内>

## 今できていること / できていないこと
- できている: <箇条書き>
- できていない: <箇条書き>

## 次の一手
- <再開したときに最初にやるコマンドまたは作業を1つだけ>

## 注意
- <ハマっている点、判断待ちの点があれば>
```

最後に、**最初に打つコマンドを1つ**だけ示してください。
迷わせないことが目的なので、選択肢を並べないでください。

## 3. 人間に渡す（このコマンドの本体はここ）

メモを出したら、そのまま続けて次の1文を人間に向けて書いてください。

> **この10行に事実と違う行が無いか、人間が1つ探してください。**
> 見つけたら「〇行目が違う」と指摘してください。訂正します。
> 見つからなければ「全部合っている」と自分で言い切ってください。

これは形式的な確認ではありません。
**自分のリポジトリが今どうなっているかを知らなければ、合っているかどうかを判定できません。**
1行も判定できなかったとしたら、それは AI に丸投げしていて状態を把握していない、ということです。
そのときは講師に見せてください。責められることではなく、今日いちばん役に立つ発見です。

指摘を受けたら、**推測で書き直さず、もう一度 1 のコマンドで事実を取り直してから**訂正してください。
